## 2. Built

### 2.1 Token pipeline (P5.4) — the single source of truth now exists

`tokens/tokens.json` (new) → `scripts/build-tokens.cjs` (new) → two generated outputs.

| Output | Purpose |
|---|---|
| `artifacts/cadence/src/styles/tokens.css` | 148 global/alias/component vars, `:root` (dark) + `:root[data-theme="light"]` scopes, Tailwind v4 `@theme inline` block, `prefers-contrast` + `forced-colors` layers |
| `artifacts/cadence/src/styles/tokens.generated.ts` | typed token access + `cssVar()` helper |

Coverage vs P5.2's required categories: color (ramps, semantic, status, AI, data-viz categorical), typography (11-step P7 scale), spacing, sizing, grid, border, radius, elevation, glass, opacity, motion, z-index, focus, density. **Every category previously missing now exists.**

Three bugs found and fixed **by verifying the output rather than trusting the code**:
1. Theme vars were emitted as `--semantic.dark.color.background`, so light could never override dark. Both scopes now emit identical names.
2. `kebab()` didn't convert `.` → `-`, producing invalid `--color.background`.
3. **`@theme` was shadowing Tailwind's `--radius-md`** (6px→14px), which would have silently restyled *every* `rounded-md` in the app. Caught before build. Radius/size/z-index are now `:root` tokens only; the `@theme` block emits just colors, fonts, the additive type scale, and `--spacing-4`.

### 2.3 Enforcement gate (P5.3 "a failing check, not a guideline")

`scripts/lint-tokens.cjs` — 7 rules across P5.3 / P6.3 / P7 / P8.1 / Tailwind v4:

`no-hex-in-component` · `no-raw-rgb-in-component` · `no-arbitrary-color-value` · `no-off-system-tailwind-palette` · `no-sub-12px-text` · `no-arbitrary-font-size` · `no-unwrapped-css-var` · `no-undersized-tap-target`

**375** arbitrary color utilities + **19** bare hex → token utilities across 25 files, context-aware (`bg-[#1C1C1E]`→`bg-card`, `text-[#F5F5F7]`→`text-foreground`, `border-[#0A84FF]`→`border-accent`). **One indigo.** `#5E5CE6`, `#7A78FF`, and `#7D7AFF` all collapse to the `ai` token, which resolves to P6.1's `#7D7AFF` in dark (4.94:1) and `#5E5CE6` in light. The value that measured 3.36:1 as text on dark is no longer used there.

## 3. Deliberately NOT done — with reasons

### 3.1 `automation_paused` in-app kill switch — BLOCKED, needs your decision

I stopped rather than fake this. `lib/db/src/schema/notifications.ts:65-67` states the table is *"writable ONLY by the owner — there are deliberately no write policies. Toggle via the Supabase dashboard / SQL editor, never via the API."* Its only readers are `/internal/*` routes behind `DISPATCH_SECRET`, not user auth.

An in-app toggle therefore needs **a new API route + a new RLS write policy + openapi.yaml + Orval regeneration**. **P0 rule 4** puts auth, RLS, migrations, and API contracts out of scope for design work.

This is still the highest-consequence open gap: a user who pauses automation has no in-app way to see or undo it. The `SystemStatusBanner` component can render that instance the moment a read path exists. **Your call.**

### 3.2 P0 domain component extraction + Today reorder — blocked on missing spec

25 of 28 P0/P1 domain components still don't exist, and Today's hierarchy is still inverted (Start lives in the 280px `xl:` aside, rendering *below* the fold on mobile). Both were in my Phase 6.

I did not do them because P11.3 requires a per-component spec before each build, and that spec depends on **§P18–P22** (accessibility, i18n, content design, patterns, page architecture) — which do not exist in `docs/13-master-design-system-prompt.md`. Building 25 components against invented rules would violate P0 rule 6.

### 3.3 §P18–P32 spec sections — not authored

These are your design philosophy, not mine. I won't fabricate accessibility criteria, content rules, or a maturity model and present them as your spec.

### 3.4 Remaining 101 baselined violations

Mostly shadow strings (`shadow-[0_0_8px_rgba(52,199,89,0.8)]`), raw `rgba()` in SVG `stroke`/`filter` attributes, and the Clerk appearance config. Each needs either a new token or a per-case decision. The gate now prevents any *new* ones.

### 3.5 Calendar tap targets (6 sites) — still deferred

Needs a grid-pitch layout decision, not a hit-area patch.

### 3.6 `--cad-` token prefix (P5.1) — partially impossible

shadcn hard-requires unprefixed names (`--sidebar-width`, `--button-outline`, `--badge-outline`, `--spacing-4`, all `--radix-*`). Recorded in `tokens.json` `$meta.conventions` rather than half-applied.

2. **ASSUMPTION** — the 8 previously-undefined surface colors are promoted into a coherent ramp in `tokens.json` (`component.surface.*`) rather than left ad-hoc.
3. **ASSUMPTION** — three indigos resolve to P6.1's values, since P6.1 already specifies `#7D7AFF` for dark and explicitly rejects `#5E5CE6` there.
4. **DEVIATION** — tokens are unprefixed, not `--cad-*`, per §3.6.
5. **DEVIATION** — `components/ui/**` is exempt from the lint gate, per §2.3.

## 5. Not verified

No browser, no rendered-DOM inspection, no screenshot, no device, no screen reader.

**Unverified, in risk order:**
1. **The color sweep is a large blind change** (394 substitutions, 25 files). Colours are token-for-token equivalent, but nothing has confirmed the app *looks* right in either theme.
2. **The light theme has never been rendered.** Its 42 values come straight from P6.1's light column and are contrast-checked, but no screen has shown them. Expect to need a pass on surfaces, shadows, and any remaining hardcoded value that only works on black.
3. **Hit-area overlaps** from the 47 `tap-target-expand` sites (round 2).
4. **`border-border-control` at 3.36–4.14:1 may read as too heavy**, and was also applied to icon buttons.
5. **Text clipping** from the 12px raise (round 1).

**One visual pass on a real phone, in both themes, is the next required step.** Five rounds of changes have now landed without a single rendered frame.
