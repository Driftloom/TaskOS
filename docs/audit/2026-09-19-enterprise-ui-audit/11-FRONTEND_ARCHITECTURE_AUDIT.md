## 2. State Management & Data Fetching Architecture

### TanStack Query Architecture
- **Configuration (`App.tsx` Lines 24–31):**
  - `staleTime: 1000 * 10` (10 seconds)
  - `retry: 1`
- **Cache Invalidation:**
  - Proper cache clearing on Clerk user change is implemented via `ClerkQueryClientCacheInvalidator` (`App.tsx` Lines 183–199). When `userId` switches, `queryClient.clear()` runs immediately to prevent cross-account cache leakage.
- **Query Key Discipline:**
  - Key factory functions generated by Orval (`getListTasksQueryKey()`, `getGetTaskSummaryQueryKey()`, `getGetMomentumQueryKey()`) are utilized consistently across `TodayPage`, `InboxPage`, `FocusPage`, and `CalendarPage`.

## 3. Critical Architectural Defects

### [Defect ARC-001] Client-Side `localStorage` Persistence Bypass
- **Affected Routes:** `/memory` (`MemoryPage.tsx`) and `/onboarding` (`OnboardingPage.tsx`)
- **Architectural Violation:** While the backend has authoritative database tables (`notification_settings`, `reschedule_settings`, `memory_facts`), these two frontend pages bypass the API layer entirely.
  - `MemoryPage.tsx` maintains facts and confirmation queues in `localStorage.getItem('cadence_memory_facts')`.
  - `OnboardingPage.tsx` serializes the user's timezone, 24h rhythm, automation mode, and Telegram Chat ID into `localStorage.setItem('cadence_user_onboarding', ...)`.
- **System Impact:**
  1. If a user runs onboarding on mobile Safari and then opens the app on a desktop Chrome browser, the desktop session does not know the user completed onboarding.
  2. The backend automated scheduling engine (`auto-reschedule-engine.ts`) and notification dispatchers run against empty or default database settings because the user's choices never reached Postgres.

### [Defect ARC-002] Dead Hook Duplication: `useKeyboardShortcuts`
- **Location:** `artifacts/cadence/src/hooks/use-keyboard-shortcuts.ts`
- **Evidence:** The hook defines a complete keyboard routing matrix (`Cmd+1..8`, `Cmd+K`, `N`, `Cmd+,`, `Cmd+P`). However, it is never imported or called in `AppShell.tsx` or `App.tsx`. Instead, `AppShell.tsx` implements an incomplete inline `useEffect` that listens for bare number keys (`1..6`) and blocks `metaKey`/`ctrlKey`.
- **System Impact:** Technical debt and conflicting keyboard behavior.

### [Defect ARC-003] Missing Auth Headers in Raw `fetch` Calls
- **Location:** `MessagingIntegrationsView.tsx` Lines 93, 110, 136, 163, 192, 218, 243
- **Evidence:** Several handlers execute raw `window.fetch('/api/integrations/...')` without extracting the Clerk session token (`await auth.getToken()`) and attaching `Authorization: Bearer <token>`.
- **System Impact:** In non-proxied or cross-origin development environments, these requests fail with 401 Unauthorized because Express `requireAuth` fails closed when no token is present.
